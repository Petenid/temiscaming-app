# Spec — Milestone 0: Foundation

Status: **complete** · 2026-10-19 · Owner develops on Windows (see §10)
Reads with: `DESIGN.md` (§4 stack, §5 language rules, §7 app structure, §9 milestones)

---

## 1. Goal

A Flutter app that runs on iOS, Android, Windows and macOS, connected to a Firebase project, where a first-time user:

1. picks **Français** or **English** (two equal buttons, neither pre-selected),
2. picks their **collection sector**,
3. lands on a placeholder **Today** screen in their language,

and never sees those two screens again unless they change the choice in **Settings**. Tests run automatically on every push.

Nothing in this milestone fetches real data or sends notifications.

---

## 2. Stack decisions to confirm

| Decision | Proposal | Why |
|---|---|---|
| App framework | Flutter (stable channel), Dart | One codebase for all four platforms; first-party desktop; built-in localization tooling (`gen-l10n`). |
| State management | Plain Flutter (`ChangeNotifier` + `ListenableBuilder`) | Two settings don't justify a library like Riverpod or Bloc (DESIGN principle 7). Easy to swap later if needed. |
| Saving settings on device | `shared_preferences` package | Standard, works on all four platforms, no account needed. |
| Localization | Flutter `gen-l10n` with ARB files (`app_fr.arb`, `app_en.arb`) | Official approach; generates type-safe Dart, so a missing string is a compile-time problem, not a runtime surprise. |
| Firebase | One project, FlutterFire CLI config, Firestore enabled with locked-down rules | Milestone 1 needs it; setting it up now proves the app can connect. |
| Cloud Functions | **Deferred to Milestone 1** | Nothing to run yet; scaffolding it now would be speculative. |
| CI | GitHub Actions: `flutter analyze` + `flutter test` | Free for public/small repos, standard for Flutter. |

## 5. Data shapes

```dart
enum AppLanguage { fr, en }          // saved as "fr" / "en"

enum Sector {
  town,     // Témiscaming town, Lac Tee and cottage roads — Tuesday
  lumsden,  // Lumsden and Letang — Wednesday
}                                    // saved as "town" / "lumsden"
```

Saved keys in `shared_preferences`: `language`, `sector`. First launch = either key missing.

**Open question carried from DESIGN §10:** *haut / bas de la ville* may need to be two sectors. The 2026 calendar puts both on Tuesday, so we ship two sectors. Because sectors are saved by ID, adding a third later doesn't break anyone's saved choice.

## 6. Screen behaviour

### Language screen (shown before anything else)
- The heading must be readable before a language is chosen, so it's shown in **both** languages, French first then English, at equal size: "Choisissez votre langue" / "Choose your language".
- Two buttons, identical size, weight and colour: **Français** and **English**. Stacked vertically (stays readable at large text sizes), full width. Neither is pre-selected or highlighted. The phone's system language is **not** used to pre-pick.
- These few bilingual strings are the only place both languages appear on one screen; they still live in the ARB files.

### Sector screen
- Fully in the chosen language.
- Two large choices, each showing the area names and the collection day, e.g. "Témiscaming town, Lac Tee and cottage roads — Tuesdays".
- A short line explaining why we ask (to show the right bin day) and that it can be changed in Settings.
- A back button returns to the language screen.

### Today (placeholder)
- App bar title "Today" / "Aujourd'hui", a short "coming soon" message, a settings icon.

### Settings
- Language (Français / English) and sector, same choices as onboarding. Changes apply immediately, no restart.

### Accessibility (DESIGN §7)
- Respects system text size; tested at 200%.
- Tap targets ≥ 48 dp (exceeds the 44 pt minimum).
- Every button has a screen-reader label in the current language.
- Nothing relies on colour alone.

## 7. Firebase setup (owner does the account steps; Claude guides)

1. Owner creates a Firebase project in the console (requires their Google account).
2. Enable Firestore in a Canadian region (`northamerica-northeast1`, Montréal) — keeps data in Quebec and is closest to users.
3. `flutterfire configure` registers the iOS, Android, macOS and Windows apps and writes `firebase_options.dart`.
4. Deploy `firestore.rules` that deny all client reads and writes for now.
5. The app initializes Firebase on start; if Firebase fails to initialize, the app still runs (onboarding doesn't need it).

Not in this milestone: FCM, notification permission screen, Cloud Functions, any Firestore data.

## 10. iOS without a Mac

The owner develops on Windows. iOS and macOS builds require Xcode, which only runs on macOS, so:

- `ios/` and `macos/` folders are generated and kept working from day one; all Dart code is shared.
- CI adds a job on a GitHub macOS runner: `flutter build ios --no-codesign`. It proves the iOS app compiles on every push (it does not produce an installable app).
- Installing on the owner's iPhone comes later, when the owner chooses: Apple Developer Program account → cloud build (Codemagic or GitHub macOS runner) with signing → TestFlight. Not part of this milestone.
